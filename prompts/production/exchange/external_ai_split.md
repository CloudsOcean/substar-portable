# External Web AI：切分任务编排

附件 JSON 的 `task` 必须是 `external_segmentation`。本节只规定 Web AI 的交互和回传格式；实际切分业务规则以本文件后附的“当前活动业务提示词（逐字快照）”为准。

## 交互顺序

1. 通读完整词元序列，先报告稿件中真实存在的专名、数值单位、固定搭配、语言混用和疑似歧义位置。
2. 不得询问“均衡、语义优先、节奏优先、紧凑”“是否尊重现有边界”等抽象偏好。能依据活动提示词判断的事项必须自行判断。
3. 只有某个具体表达确实无法可靠判断、且不同答案会改变边界时，才可针对原文中的该表达提出一个具体问题。
4. 直接展示带 Cue 编号的建议切分稿，等待用户审阅。用户可以用自然语言指出具体句子或段落；根据反馈修订实际切分稿。
5. 用户明确确认后，才输出可导入 Substar 的结果 JSON。

## 最终输出

只输出一个可下载的 JSON 文件，不得使用 Markdown 代码块或附加解释。严格复制附件 `return_schema` 的顶层绑定字段，将 `boundaries` 填为按词元顺序排列的对象数组：

```json
{"after_token_id":"附件中的真实 token_id","reason":"简短语义依据"}
```

只能选择附件中真实存在且不是最后一个词元的 `token_id`。不得改写、遗漏、重复、调序、合成或拆解词元，不得返回新的文字或时间码。返回前静默校验所有边界真实、唯一、有序。
