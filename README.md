# Substar

> **从词级时间开始，把自动字幕变成一份真正能继续编辑的工作稿。**

做一份自动字幕已经不难了。

真正费时间的，往往是生成之后：一句话切得不自然，要重新拆；专名和数字识别错了，要回头找；翻译和原文对不上，要重新整理；时间轴一改，前后又跟着乱。

视频只有几分钟时，这些问题还能一条条处理。到了访谈、播客、节目和其他长视频里，前面自动化省下来的时间，很容易又被后面的返工吃掉。

**Substar 想解决的就是这一段。**

它从“每一个词在什么时候出现”开始组织字幕。听写、切分、校准、翻译、审阅和人工编辑，都围绕同一条词级时间线工作。

模型可以帮你理解语言、寻找边界和生成译文，但时间事实、字幕结构和最后的修改权，始终留在同一个可追踪的项目里。

最终得到的不是一份“生成完就尽量别碰”的 SRT，而是一份可以继续拆、合、改、查、校对和交付的字幕工作稿。

当前版本：**2.0.3** · Windows 10/11 x64 透明便携版

[下载最新版本](https://github.com/CloudsOcean/substar-portable/releases/latest)

## 为什么从词开始

很多字幕工作流的基本单位是一整句：

```text
字幕 = 文本 + 开始时间 + 结束时间
```

这当然简单。

问题是，只要真正开始编辑，**一句往往还是太大了。**

比如一句字幕切得不好，你想把最后三个词挪到下一条。文本很好拆，但新的时间点从哪里来？如果底层只有整句的开始和结束时间，就只能重新估算。

Substar 的做法不同。

当前听写路线使用阿里云百炼 **Qwen 文件听写**，取得识别文本、说话人证据和原生词级时间。每个词元及其时间会先保存下来，成为后续工作的事实层。

Cue 只是连续词元的一种组合：

```text
Word1  Word2  Word3  Word4  Word5  Word6
└──────── Cue A ────────┘ └── Cue B ──┘
```

所以重新切字幕时，很多时候并不是“重新猜一个时间”，而只是决定：

**边界应该放在哪两个词之间。**

Cue 的开始时间来自第一个词，结束时间来自最后一个词。模型负责判断语义边界，不需要重写底层时间轴。

它带来的好处很直接：

- **时间事实更稳定**：AI 判断怎么切，但不能随意编造每个词的起止时间。
- **切点更精确**：字幕边界落在真实词元之间，而不是重新估算整句时间。
- **修改更容易追踪**：词元、Cue、译文、参考稿差异和 AI 修改保留对应关系。
- **编辑更自然**：拆分、合并、改文本、调时间，面对的始终是同一条媒体时间线。
- **交付版本更一致**：上行、下行、双语字幕和完整工程都来自同一个项目事实层。

人工补充或参考稿独有、却没有听写时间证据的内容会被单独标记，不会伪装成识别引擎原本返回的词级时间。

## 一条字幕任务是怎么跑完的

```mermaid
flowchart LR
    A["视频或音频"] --> B["Qwen 云端听写"]
    B --> C["原生词级时间线"]
    C --> D["AI 切分或参考稿标点切分"]
    D --> E["词级编辑器"]
    E --> F["AI 校准与翻译"]
    F --> G["外部 AI 审阅与人工收尾"]
    G --> H["字幕文件或完整工程"]
```

### 1. 听写

把视频或音频拖入切分页，也可以一次处理多个素材。Substar 会先在本机通过 FFmpeg 准备音频，再交给 Qwen 文件听写服务。

支持的输入格式包括：MP4、MOV、MKV、AVI、WEBM、M4V、MP3、WAV、M4A、AAC、FLAC 和 OGG。

可以设置原文语言、目标语言，以及不同语言的单条字幕字符数上限。Qwen 听写增强支持任务级 Prompt 和临时多语言热词；还可以输入节目内容与识别重点，让当前文本模型协助填写 Prompt 和热词建议。

这些内容只属于当前素材。项目创建成功后，节目说明、Prompt、临时热词和自定义切分符号会自动清理。

### 2. 切分

Substar 提供三条路径：

| 模式 | 用途 |
| --- | --- |
| **仅使用听写结果** | 直接沿用听写服务返回的句级边界 |
| **AI 辅助切分** | 结合上下文、语法结构和字符上限，在词级时间线上重新组织 Cue；参考稿可选 |
| **按参考稿标点切分** | 使用参考稿校正词元，并按指定的尾部标点机械确定边界；参考稿必选 |

参考稿支持 TXT、DOCX 和 SRT。系统会保留听写结果与参考稿之间的替换、插入和保留差异，让编辑者决定最终采用哪一版。

切分符号会按原文语言提供预设，也可以自定义。数字、版本号、时间、缩写、邮箱和网址内部的标点会作为词汇内容保护，避免误切。

### 3. 词级编辑

进入编辑器后，Cue 列表、媒体预览和时间轴会保持联动。

- 右键词元间隙：从当前位置切分 Cue。
- 右键行尾辅助点：与下一条 Cue 合并。
- 双击词元：直接修改文字。
- 拖选多个词元：合并或标记删除。
- 拖动时间轴边界：调整字幕出现和结束时间。
- 点击相邻 Cue 的控制线：在联动边界和单独调整之间切换。
- 音频与视频共用同一媒体时钟，Cue、波形和预览保持同步。

查找与替换只处理完整词元，不会误命中另一个词内部。原文“替换为空”会把命中词元标记为可恢复的删除；译文“替换为空”会直接移除对应文本。最近一次替换或全部替换可以在左侧立即撤销。

### 4. AI 校准

AI 校准用于处理标点、英文大小写、专有名词、数字和可能的听写错误。你可以补充本次要求，例如重点检查品牌、机构或人名。

它不会重写整篇稿件，而是在现有词元上提交受约束的修改：

- 替换单个词元；
- 调整允许的标点和大小写；
- 将同一 Cue 内属于一个书写单位的连续词元合并，例如 `u` + `s` → `U.S.`；
- 保留具体修改、问题标记和审计结果。

AI 校准不能跨 Cue 合并，也不能借合并操作改写整段句子。

### 5. AI 翻译

翻译支持两种模式：

- **多对多翻译**：先结合上下文理解完整意义，再把译文映射回合适的 Cue；适合自然语序与字幕节奏并重的成稿。
- **逐行翻译**：按 Cue 逐条生成译文，适合必须维持严格行级对应的场景。

一句原文可以对应多句译文，多句原文也可以共同构成一个意义单元。映射关系保存在项目中，不依赖“第几行必须对第几行”的脆弱假设。

### 6. 外部 AI 审阅

外部 AI 审阅不会调用 Substar 中配置的模型，也不会修改工程。它只生成一份可以复制或下载的审阅材料，交给任意网页端 AI 使用。

审阅范围支持：

- **全部**；
- **当前 Cue**；
- **指定范围**，例如 `12-34`、`12；34；55` 或 `12，45，66`。

当前与指定范围会自动附带前后各 5 条 Cue 作为上下文。你也可以写下自己的疑问，让外部 AI 只针对标为“审阅”的 Cue 给出判断。

### 7. 打轴和收尾

编辑器还提供：

- 上行与下行分别配置的标点删除、替换为空格规则；
- 默认开启的向前智能吸附，寻找可信起音并保留 20 ms 前置静音；
- 按阈值处理相邻字幕小空隙的向后吸附；
- 自动吸附预览、执行与撤销；
- 简体、通用繁体、台湾繁体和香港繁体显示/导出投影；
- 四色说话人标记及自定义名称；
- 项目版本、自动保存和完成状态。

## 模型、任务与失败恢复

Substar 把听写任务、切分任务、AI 校准和翻译统一交给可恢复的后台任务系统。任务卡会显示真实阶段与进度，离开当前页面后仍可继续运行。

文本模型服务采用 OpenAI Chat Completions 兼容接口。快速开始可以直接配置智谱 GLM；完整设置也支持 DeepSeek 等兼容服务。

配置多个模型服务后，可以在“任务信息”中为当前项目指定模型。项目会冻结服务商、Base URL、模型、认证方式和凭据引用，后续修改全局设置不会悄悄改变正在处理的任务。

AI 校准或翻译失败时，任务卡会提供：

1. 模型选择；
2. 重试；
3. 前往模型设置。

已经完成的处理单元会保留；内容修复与网络传输重试彼此分离。无法完成的翻译会留下可编辑的空目标行和问题标记，而不是让整个项目失去编辑入口。

## 可以导出什么

| 导出项 | 内容 |
| --- | --- |
| **上行字幕** | 当前上行轨道的 SRT |
| **下行字幕** | 当前下行轨道的 SRT |
| **上下行单行字幕** | 在同一行组合上下行内容 |
| **上下行双行字幕** | 每条 Cue 使用两行展示上下行内容 |
| **字幕工程** | 包含媒体和当前修订、可在另一台电脑继续编辑的完整 ZIP |

字幕导出文件按“任务名＋字幕类型＋第 N 次导出”命名。编辑器中的上下行显示顺序也是导出的最终顺序。

## Windows 便携版使用

普通用户不需要安装 Python、FFmpeg、CUDA 或本地模型。

1. 从 [GitHub Releases](https://github.com/CloudsOcean/substar-portable/releases) 下载 Windows x64 ZIP。
2. 将 ZIP **完整解压**到一个普通、可写的文件夹。
3. 双击 `启动_Substar.cmd`；程序默认打开 `http://127.0.0.1:8769/`。
4. 首次使用时配置：
   - 阿里云百炼 Qwen 文件听写 API Key；
   - 至少一个用于 AI 切分、校准和翻译的文本模型服务。
5. 回到“切分”页，拖入视频或音频并创建项目。

发行包采用透明目录结构，代码、网页、Prompt、Schema、固定 Python 运行时和 FFmpeg 都保留为可检查的独立文件。不要只复制其中某个文件运行。

需要停止后台服务时，运行 `停止_Substar.cmd`。

### 数据目录

首次运行后，程序会在安装目录创建：

```text
data/
├─ .substar-workbench/   # 设置、加密凭据和任务数据库
└─ projects-v2/          # v2 字幕项目
```

如需迁移到另一台电脑，请复制完整 `data/`，不要只复制凭据密文或其中某个项目目录。

Substar 2.x 不扫描、读取、导入或迁移旧版 `data/projects/` 和旧运行数据库。旧数据可以原位保留，但不会出现在 v2 工作台中。

## 数据与隐私

Substar 本身不运营云端中转服务，也不收集遥测。

运行项目时会发生以下数据流：

1. 媒体在本机通过 FFmpeg 转换为听写音频。
2. 听写音频、语言、Prompt 和临时热词发送到用户配置的 Qwen 云端服务。
3. 字幕文本、词库、参考稿片段和任务提示可能发送到用户选择的文本模型服务，用于切分、翻译或校准。
4. 外部 AI 审阅材料只有在用户自行复制或下载后，才会由用户交给所选择的外部服务。
5. 项目、任务数据库、设置、凭据密文和便携密钥保存在本机 `data/`。

云服务的计费、内容保留、地域和隐私政策由相应服务商决定。删除本机项目不会自动删除服务商已经接收的数据。详见 [PRIVACY.md](PRIVACY.md)。

## 从源码运行

开发环境建议使用 Python 3.11：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-release.txt
.\.venv\Scripts\python.exe app.py
```

运行测试：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider
node --test tests\*.test.js
```

完整架构、模块边界、API、Worker 和交付链见 [系统地图](docs/architecture/system-map.md)；机器可读权威为 [system-map.json](docs/architecture/system-map.json)。便携版目录契约见 [portable-layout.md](docs/architecture/portable-layout.md)。

### 构建 Windows 发行包

准备 Windows x64 的 `ffmpeg.exe` 与 `ffprobe.exe`，然后执行：

```powershell
$env:SUBSTAR_FFMPEG_DIR = "C:\path\to\ffmpeg\bin"
.\scripts\build-windows.ps1 -Python .\.venv\Scripts\python.exe
```

构建结果位于 `dist/Substar/` 和 `dist/Substar-Windows-x64-portable.zip`。

推送 `v*` 标签后，GitHub Actions 会重新运行 Python 与 Node 测试、构建透明 Windows 包，并把 ZIP 上传到 GitHub Releases。

## 当前边界

- 当前发行版是 Windows x64 透明便携包，不是签名安装程序。
- 当前听写后端为 Qwen 云端文件听写，不包含本地 ASR 引擎或本地模型。
- 外部 AI 审阅只生成材料，不会自动把外部 AI 的结论写回项目。
- v2 项目格式与旧版隔离，不提供旧项目自动迁移。
- 本 Beta 仅供评估；再分发、再授权和衍生作品权限以 [LICENSE](LICENSE) 为准。

问题报告请附上版本号、复现步骤、任务错误码，以及删除 API Key 和媒体内容后的日志片段。请勿提交任何密钥。

## Substar 在解决什么

Substar 并不只是把“听写 → 切分 → 翻译 → 导出”串起来。

如果只是串几个模型调用，真正开始人工修改之后，很快还是会碰到原来的问题：

时间从哪里来？

这一刀为什么切在这里？

译文对应哪一段原文？

修改之后，其他版本会不会漂掉？

这也是 Substar 为什么把**词级时间和项目结构**放在整个系统的底层。

听写事实、词级时间、Cue 边界、译文、参考稿差异、AI 处理结果和人工修改始终待在同一个可追踪项目里。

**模型负责加速，人负责判断；自动化可以大胆往前走，但最后的字幕仍然应该是你能看懂、能修改、能复核的东西。**
